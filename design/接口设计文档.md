# 个人健康管理与运动追踪平台接口详细设计文档（REST API v1）

## 1. 文档范围
1. 定义 `/api/v1` 下全部接口的 REST 规范。
2. 定义请求体 DTO、响应体 VO、持久化对象 PO。
3. 统一响应体、错误码、分页结构与鉴权规则。

## 2. REST 规范

### 2.1 基本规则
1. 协议：`HTTPS`。
2. 路径风格：资源名复数，动作用 `PATCH` 状态流转或子资源。
3. 数据格式：`application/json; charset=utf-8`。
4. 时间格式：`yyyy-MM-dd HH:mm:ss`（或 `yyyy-MM-dd`）。
5. 幂等性：`GET/PUT/DELETE` 幂等，`POST` 非幂等。

### 2.2 鉴权规则
1. Header：`Authorization: Bearer <token>`。
2. 角色：`SUPER_ADMIN`、`ADMIN`、`USER`。
3. 普通用户仅能访问本人数据，管理端接口仅管理员可访问。

### 2.3 统一响应体
```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "traceId": "a2bc3d4e5f6g",
  "timestamp": "2026-05-22 20:00:00"
}
```

### 2.4 通用错误码
| code | 含义 | 场景 |
| --- | --- | --- |
| `0` | 成功 | 请求成功 |
| `40001` | 参数错误 | 必填缺失、格式不合法 |
| `40101` | 未登录 | token 缺失/失效 |
| `40301` | 无权限 | 越权访问 |
| `40401` | 资源不存在 | id 对应记录不存在 |
| `40901` | 资源冲突 | 账号/手机号/邮箱重复 |
| `42201` | 业务校验失败 | 状态流转非法、健康数据异常 |
| `50001` | 系统异常 | 未知错误 |

## 4. 接口详情（逐接口）

说明：所有响应外层均为 `ApiResponse<T>`，成功 `code=0`。

### 4.1 认证与账户
| 接口 | 方法 | 路径 | 鉴权 | 请求 DTO | 响应 VO | 业务规则 |
| --- | --- | --- | --- | --- | --- | --- |
| 用户注册 | POST | `/api/v1/auth/register` | 否 | `RegisterReqDTO` | `Long`(userId) | 手机号/账号唯一 |
| 用户登录 | POST | `/api/v1/auth/login` | 否 | `LoginReqDTO` | `LoginVO` | 图形验证码必校验 |
| 管理员登录 | POST | `/api/v1/admin/auth/login` | 否 | `LoginReqDTO` | `LoginVO` | 查 admin 表，图形验证码必校验 |
| 退出登录 | POST | `/api/v1/auth/logout` | 是 | 无 | `null` | token 失效化 |
| 找回密码 | POST | `/api/v1/auth/forgot-password` | 否 | `ForgotPasswordReqDTO` | `null` | 校验验证码与身份 |
| 修改密码 | PUT | `/api/v1/auth/password` | 是 | `ChangePasswordReqDTO` | `null` | 校验旧密码 |
| 获取图形验证码 | GET | `/api/v1/auth/captcha` | 否 | 无 | `CaptchaVO` | 返回 Base64 图片 + captchaKey |

## 5. 非功能与安全要求（接口层）
1. 普通查询/提交：`<=1s`，复杂统计/报告：`<=5s`。
2. 参数校验必须前后端双校验。
3. 所有写接口必须写入 `system_log`。
4. 防护要求：SQL 注入、XSS、CSRF、越权访问。
