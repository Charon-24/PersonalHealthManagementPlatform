# 个人健康管理与运动追踪平台数据库设计文档（V1.0）

## 1. 文档说明

### 1.1 目的
定义平台数据库的实体关系、表结构、约束、索引与数据校验规则，作为后续建表与数据层开发依据。

### 1.2 数据来源
1. `requirement/requirement.md` 文本需求。
2. `requirement.md` 内嵌图片 `wps8~wps18`（表结构图）和 `wps7`（ER 图）。

## 2. 实体关系设计

### 2.1 核心关系
1. `role 1 - N admin`
2. `user 1 - 1 health_file`
3. `user 1 - N health_data`
4. `user 1 - N sport_plan`
5. `sport_item 1 - N sport_plan`
6. `sport_plan 1 - N sport_record`
7. `user 1 - N sport_record`
8. `diet_recipe 1 - N diet_record`
9. `user 1 - N diet_record`
10. `admin/user 1 - N system_log`

## 4. 约束与索引

### 4.1 约束
1. 唯一约束：`admin.username`、`user.username`、`user.phone`、`user.email`。
2. 外键约束：`admin.role_id -> role.id`。
3. 外键约束：`health_file.user_id -> user.id`、`health_data.user_id -> user.id`。
4. 外键约束：`sport_plan.user_id -> user.id`、`sport_plan.sport_item_id -> sport_item.id`。
5. 外键约束：`sport_record.user_id -> user.id`、`sport_record.plan_id -> sport_plan.id`、`sport_record.sport_item_id -> sport_item.id`。
6. 外键约束：`diet_record.user_id -> user.id`、`diet_record.recipe_id -> diet_recipe.id`。

### 4.2 枚举
1. `user.status`、`admin.status`、`sport_item.status`、`diet_recipe.status`：`0=禁用,1=启用`。
2. `sport_plan.status`：`0=暂停,1=进行中,2=完成`。
3. `system_log.user_type`：`管理员/普通用户`。

### 4.3 索引建议
1. `health_data(user_id, record_date)`。
2. `sport_record(user_id, sport_time)`。
3. `diet_record(user_id, record_time)`。
4. `sport_plan(user_id, status)`。
5. `system_log(user_type, user_id, create_time)`。

## 5. 数据校验规则

### 5.1 健康数据
1. 核心字段：血压、血糖、心率。
2. 异常校验示例：`200/120 mmHg` 应返回“血压数值异常”。
3. 推荐阈值：收缩压 `60~250`，舒张压 `40~150`，心率 `30~220`，睡眠 `0~24h`，体重 `20~300kg`。

### 5.2 运动数据
1. `plan_cycle` 仅允许 `周/月`。
2. `sport_frequency`、`sport_duration` 必须为正整数。
3. `sport_time` 不得晚于当前系统时间（允许配置容忍窗口）。

### 5.3 饮食数据
1. `food_name` 与 `intake` 必填。
2. `record_time` 不得晚于当前系统时间。

## 6. 风险与待确认项
1. 图片分辨率有限，个别字段可能需与最终 SQL 冻结稿二次核对。
2. 健康指标阈值是否按年龄/性别动态配置待确认。
3. 是否增加软删除字段（如 `deleted`）待确认。
